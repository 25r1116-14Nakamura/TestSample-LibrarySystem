
# 課題:ECサイトのクーポン適用機能テスト設計

## 1.演習の目的

単一の入力値チェック(点)から、ユーザーの行動(線)を意識した「正常系・異常系」の切り分けができるようになること。
また、**5W1H**や**品質特性**の視点を取り入れ、仕様書の裏側にあるリスクを特定する

## 2.課題の前提条件

* **機能：**購入手続き画面で「クーポンコード」を入力し、適用ボタンを押すと割引される。
* **仕様**
  * 1回の注文につき、1つのクーポンのみ利用可能
  * クーポンには、「有効期限」と「最低利用金額(3000円以上)」がある。
  * 一度使用したクーポンは二度と使えない。

### 【タスク1】5W1Hによるテスト条件の抽出

**5W1H**のフレームワークを使って、どの様な状況でこの機能が使われるか条件を洗い出してください。

1. Who（誰が）
* 属性：

  * ゲスト購入（会員登録なし）ユーザー

  * 新規会員（初回クーポン対象）

  * 既存会員（リピーター）

ブラックリスト入り（利用停止中）のユーザー

* 悪意の有無：
  * 純粋に割引を受けたいユーザー

  * 複数アカウントを作成してクーポンを乱用しようとするユーザー

  * 転売目的などで、スクリプト（Bot）を使って自動購入を試みるユーザー

1. When（いつ）
* 有効期限：
  * 有効期限内（正常系）

  * 有効期限切れ（異常系）

  * 有効期限の境界値（23:59:59 滑り込み vs 00:00:00 直後）

* システムのタイミング：
  * キャンペーン開始直後のアクセス集中時

  * 決済処理中に、管理者が裏側で「クーポンの無効化」操作を行った瞬間

  * メンテナンス明け直後

1. Where（どこで / 環境）
* デバイス：

  * PCブラウザ（Chrome, Edge等）

  * スマホブラウザ（Safari, Chrome）

  * アプリ内ブラウザ（WebView）

ネットワーク状態：

* 安定したWi-Fi

* 移動中の不安定な4G/5G（適用ボタンを押した瞬間に通信が切れる）

複数のタブ（タブAでクーポン適用後、タブBで同じクーポンを適用しようとする）

1. What（何を / データ）
* クーポンコード：

  * 正しいコード（半角英数）

  * 誤ったコード（タイプミス）

  * 無効な文字（全角、スペース、記号、SQLインジェクション文字列 ' OR '1'='1）

  * 空文字（何も入れずにボタン押下）

  * 既に自分が使用済みのクーポンコード

  * 他人が使用済みのクーポンコード（ユニークコードの場合）

* カート金額（最低利用金額3000円の境界値）：

  * 3001円（適用可）

  * 3000円（適用可・境界値）

  * 2999円（適用不可・境界値）

クーポン適用後に商品を削除して2999円になった場合（再計算されるか？）

1. Why（なぜ / 目的）
* 正常な動機：

  * 少しでも安く買いたいから。

テスト・攻撃的な動機：

* 「1回限り」の制限を突破し、無限に割引を受けられるか試すため。

* 最低利用金額のチェックをすり抜けて、タダ同然で商品を得るため。

* サーバーに負荷をかけ、二重注文（Race Condition）を誘発させるため。

1. How（どのように / 手順）
* 操作手順：

  * 正しく入力して「適用」ボタンを1回クリック。

  * 「適用」ボタンを高速連打（Double Submit対策の確認）。

  * 適用後にブラウザの「戻る」ボタンで戻り、再度適用する。

  * 決済完了画面まで行ってからブラウザを閉じ、再度カートに戻って決済する（使用済みフラグが立つタイミングの確認）。

  * APIを直接叩いて、画面UIを介さずにリクエストを送る（Bypass）。

### 【タスク2】観点別の「正常系・異常系」分類（点のテスト）

タスク1で出した条件を、**4つのテスト観点**に基づいて分類し、それぞれ「正常系」か「異常系」かを判断してください。

#### 1. 機能的観点 (Functional)

| 分類 | テスト内容 | 期待値・判定基準 |
| --- | --- | --- |
| **正常系** | 有効なクーポンコードを入力し、適用ボタンを押下する | 割引が適用され、合計金額が減算されること。 |
| **正常系** | クーポン適用後に「取り消し」を行う | クーポンが外れ、合計金額が元に戻ること。 |
| **異常系** | 有効期限切れのクーポンコードを入力する | 適用されず、「有効期限切れです」等のエラーが表示されること。 |
| **異常系** | 存在しない（デタラメな）コードを入力する | 適用されず、「コードが見つかりません」等のエラーが表示されること。 |
| **異常系** | 2つ目のクーポンを追加で入力する（1回1枚制限） | 後から入力した方で上書きされるか、あるいはエラーではじかれること。（仕様によるが、重複適用はNG） |

#### 2. データの観点 (Data)

| 分類 | テスト内容 | 期待値・判定基準 |
| --- | --- | --- |
| **正常系** | カート合計が **3000円（境界値）** で適用する | 適用されること。（「以上」なので3000円はOK） |
| **正常系** | カート合計が 3001円 で適用する | 適用されること。 |
| **異常系** | カート合計が **2999円（境界値）** で適用する | 適用されず、「3000円以上で利用可能です」等のエラーが出ること。 |
| **異常系** | **全角文字**でコードを入力する | エラーになるか、システム側で半角に自動変換して適用されること。 |
| **異常系** | **SQLインジェクション文字**（`' OR '1'='1` 等）を入力する | 無害化（サニタイズ）され、単なる「無効なコード」として扱われること（システムエラーにならないこと）。 |
| **異常系** | **空欄（何も入力しない）**でボタンを押下する | 「コードを入力してください」等のバリデーションエラーが出ること。 |

#### 3. 状態の観点 (State)

| 分類 | テスト内容 | 期待値・判定基準 |
| --- | --- | --- |
| **正常系** | **未使用**のクーポンを持っている状態で適用する | 適用されること。 |
| **異常系** | **使用済み（過去に決済完了済み）**のコードを再入力する | 「既に使用済みのクーポンです」とエラーが出ること。 |
| **異常系** | **【重要】** クーポン適用後に商品を削除し、合計が **2999円以下** になる | **自動的にクーポンが外れること。**（適用されたまま決済できてはいけない） |
| **異常系** | 未ログイン（ゲスト）状態でクーポンを入力する | ログイン画面へ誘導されるか、会員限定ならエラーになること。 |
| **異常系** | **ブラックリスト（利用停止）ユーザー**が適用を試みる | 適用不可、または決済時にブロックされること。 |

#### 4. 表示の観点 (Display)

ユーザーに見える情報が正しいかどうかの確認です。

| 分類 | テスト内容 | 期待値・判定基準 |
| --- | --- | --- |
| **正常系** | 割引額の表示（マイナス表記） | 「-500円」のように、割引分が明確に表示されていること。 |
| **正常系** | 最終支払金額の計算表示 | （小計 - クーポン + 送料）の計算結果が1円のズレもなく正しいこと。 |
| **異常系** | エラーメッセージの視認性 | 入力欄の近くに、赤字などでわかりやすくエラーが表示されること。 |
| **異常系** | 適用ボタンの連打時の表示 | ローディング表示が出るなどして、二重送信を防ぐUIになっていること。 |

### 【タスク3】ユーザーシナリオの設計

* カート画面→確認画面(クーポン適用)→割引反映→注文確定
  * ハッピーパス(正常系)：ユーザーが最もスムーズに購入を完了する流れ
    * ステップ
      * 商品を3500円分カートに入れる
      * 確認画面で有効なクーポンコードを入力
      * 適用ボタンを押下
      * 割引の反映を確認
      * 注文確認ボタンを押下
* 確認
  * 最後までエラーが出ず、クーポンは使用済みになっている。

  * 代替パス(準標準系)：コードを打ち間違えるが、修正して最終的に購入できる流れ。
    * ステップ
      * 商品を3500円分（最低利用金額以上）カートに入れる。
      * 確認画面で**無効なクーポンコード（例: 桁数不足、タイプミス）**を入力する。
      * 適用ボタンを押下する。
      * 「コードが正しくありません」等のエラーメッセージが表示されることを確認する。
      * エラーを確認後、正しい有効なクーポンコードに入力し直す。
      * 再度、適用ボタンを押下する。
      * 割引が正しく反映されたことを確認し、注文確定ボタンを押下する。
    * 確認
      * 最初のエラー時にシステムが落ちたり、誤って適用されたりしないこと。
      * 最終的に正しいコードで割引が適用され、注文が完了すること。

* エラーパス(異常系)：決済直前にクーポンの有効期限が切れてしまい、購入に失敗する流れ。
  * ステップ
    * 商品を3500円分カートに入れる。
    * 有効期限**ギリギリ（例: 23:59:50）**のクーポンコードを入力し、適用ボタンを押下する。
    * 画面上で割引が反映されている状態（適用済み）にする。
    * ここで日付が変わる（00:00:01）まで待機する、またはシステム時間を進める。
    * 有効期限が切れた状態で、注文確定ボタンを押下する。
  * 確認

    * 注文が確定されず、エラー（「クーポンの有効期限が切れています」等）で弾かれること。
    * または、画面がリロードされ、**割引が適用されていない金額（定価）**に戻っていること。
    * 【重要】 「画面上は割引されているのに、決済されたら定価だった」や「期限切れなのに割引で決済されてしまった」という不整合が起きないこと。
